# AssetSquare Interface Specification

## 1. 현재 결정

자산제곱 사고모형의 완전한 자동화는 데이터·분석 계층이 검증된 뒤 수행한다.

현재 Phase에서 구현할 것은 자산제곱의 결론이 아니라 **나중에 사고모형이 사용할 근거 구조와 인터페이스**다.

---

## 2. 출력 분류

```text
[원문 직접]
공시·실적·공식 데이터에 직접 존재

[구조적 추론]
둘 이상의 사실을 연결한 인과 판단

[최신 확인]
현재 시점의 데이터로 재검증

[미확인]
공개 데이터 또는 현재 소스로 확인 불가
```

---

## 3. 가설 상태

```text
NEW
STRENGTHENING
UNCHANGED
WEAKENING
REVERSING
INVALIDATED

```

- 원문
- 출처
- 기준일
- 확신도

- 가설
- 기간
- 상태
- 근거
- 반대 근거
- 미확인
- 시나리오 영향

- 원인
- 결과
- 전달경로
- 강도
- 시차
- 근거
- 반론

### InvalidationCondition
- 조건

- 관측식

- 변경 주체
- 변경 시각

## 5. Phase 1 요구

Phase 1에서 전체 규칙 엔진을 구현하지 않는다.

대신 다음을 보장한다.

- 공통 데이터 계약이 향후 Evidence 참조를 막지 않음
- SourceRecord를 통해 원문 추적 가능
- 분석 결과에 입력 데이터 ID를 저장 가능
- 문서에 가설·무효화 구조가 정의됨
- 패킷 export의 확장 위치가 존재
- 테이블 구현 여부는 Phase 1 계획에서 최소 범위로 결정

---

## 6. 후속 사고모형

후속 Phase에서 다음을 단계적으로 검증한다.

```text
매크로 변화
→ 산업구조
→ 기업 수주·매출·마진
→ 시장 기대
→ 가격 반영도
→ 6~18개월 손익비
→ 반론
→ 무효화
```

자산제곱 원문 248개를 한 번에 거대한 프롬프트로 넣지 않는다.

권장 과정:

1. 원문 규칙 후보 추출
2. 원문 출처 연결
3. 상충 규칙과 최신 문서 우선순위
4. 테스트 사례 작성
5. 소규모 섹터 적용
6. 실제 결과 검토
7. 점진적 확대

---

## 7. 금지사항

- 자산제곱 이름만 붙인 일반 요약
- 원문 근거 없는 규칙 생성
- 기관 매수만으로 자동 가설 강화
- 가설 강화만 기록하고 약화·반전 누락
- 현재 가격을 무시한 좋은 기업 나열
- 무효화 조건 없는 투자 가설
- GPT 결론을 사실 데이터로 저장
